  mscorlib

Behavior: locates Schedule I (default Steam path, Steam registry/library
folders, then a bounded fixed-drive search), optionally attaches the runtime
package files into the game folder after user confirmation, and starts

the selected game folder; no elevation, network access, persistence, or
deletion is performed.

Live-control layer
------------------
The GUI can open without a private companion DLL, but live game operations need:
  Mods\ScheduleIControlBridge.dll
  version.dll (MelonLoader bootstrap)
  MelonLoader\ (0.7.3.2525 runtime and generated IL2CPP interop assemblies)
  UserData\Loader.cfg (current loader configuration)
  the matching Schedule I game installation
  x64 .NET 6.0.36 registered on Windows

The bridge resolves Harmony, Il2CppInterop, Newtonsoft.Json, Unity, FishNet,
ScheduleOne, and generated Assembly-CSharp references from the included
MelonLoader tree and the matching game-generated environment. Plugins and
UserLibs were empty and are not dependencies.

Patched component
-----------------
MelonLoader\net6\Il2CppInterop.Generator.dll is Il2CppInterop 1.5.3 with three
surgical null-safety guards (Pass11ComputeTypeSpecifics, RewriteTypeRef, and
JudgeSpecificsByOriginalType) so Schedule I 0.4.6f11 metadata that references
stripped Unity types (for example UnityEngine.Camera+GateFitMode) generates
interop assemblies instead of crashing. All other files in the MelonLoader
tree are the official 0.7.3.2525 CI build and official Il2CppInterop 1.5.3
binaries. Interop for game build 24484559 is pre-generated in Il2CppAssemblies.

Optional state, not dependencies
--------------------------------
UserData\ScheduleIControlBridge.market-values.json
UserData\ScheduleIControlBridge.customer-allowances.json
UserData\ScheduleIControlBridge.sell-price-limit.json (created only after apply)

Those profiles were deliberately excluded from this runtime package so the ZIP
does not silently copy the user's current economic settings or rollback history.
